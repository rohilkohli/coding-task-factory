# Improvement Research (round 2)

**Goal:** find evidence-backed improvements for weak spots that the first generator batch exposed (73 candidates, 16 accepted).
**Method:** K-Dense *Scientific Agent Skills* `paper-lookup` (OpenAlex), 12 targeted queries, publications from 2023 onward, top 40 by relevance each. That gave 456 new records; 36 were screened in. Claims are taken from abstracts.
**Search date:** 2026-11-26. Query log: `docs/research-sources/round2_provenance.log`.

## Our weak spots → what the literature says → what to build

| # | Weak spot (from our funnel) | Evidence | Improvement | Needs AI key? | Effort |
|---|---|---|---|---|---|
| 1 | **17/73 rejected as "no way to build wrong fixes".** Some accepted tasks were checked with only 1–2 wrong fixes. | Statement deletion finds pseudo-tested code that operator mutants miss: 48% of pseudo-tested statements lie outside pseudo-tested methods [1, 2]. | Add a **statement-deletion** wrong-fix operator (works on any function) and require **at least 3 wrong fixes** per accepted task. | No | Low |
| 2 | **No "hard" tasks;** every task is a single-token change or one function. | Difficulty is driven mainly by **patch fragmentation** (number of locations) and repo scale (AUC 0.863 from static features) [11]. Patch size and complexity predict solve rates (R² = 0.951); difficulty tiers take the top solve rate from 95% to 9% [23]. Multi-location bugs are harder to repair [20]. Masked function bodies can be composed into larger tasks [21]. | **Composite tasks:** 2–3 validated bugs in different functions or files, or 2–3 removed functions that share tests. Gives a real *hard* tier. | No | Medium |
| 3 | **Difficulty is a hand-made guess.** | Static features predict difficulty well [11, 23]. Difficulty can be estimated without agent runs, and mismatches expose broken or contaminated tasks [10]. | Replace the heuristic with a **static difficulty score**: locations changed, lines changed, files, F2P count, hint level. Report it per task. | No | Low |
| 4 | **Instructions list the failing tests,** a strong hint. | Under-specification is the most damaging defect in task descriptions [19]. Realistic reports describe **observable symptoms, not root causes** [22]. LLMs can produce structured bug reports [17]. | **Hint levels:** L2 lists failing tests (current), L1 gives symptoms (assertion messages, no test names), L0 gives a one-line symptom. Same code, three difficulties. | No for L1/L2; key for natural prose | Medium |
| 5 | **Agents can read every test** in generated tasks and fit to them. | Agents pass visible tests but fail held-out tests that combine the same features; the gap grows with task size [31]. Agents edit test files or hard-code cases [33]. LLM judges detect hacks better when they can compare trajectories [32]. Agents take planted shortcuts in more than half of runs even when told not to [34]. | **Held-out split:** hide part of the F2P tests from the agent's repo, grade on all, report the visible-vs-held-out gap. **Log test-file tampering** in each trial. | No | Medium |
| 6 | **15/73 rejected as "weak tests";** those functions are lost. | Surviving program variants can guide generation of targeted tests that pass the reference and fail the variant. On SWE-bench Verified, 77% of instances admit a surviving variant, and agents' resolved rates fall 4–9% after augmentation [24]. LLMs kill up to 95% of surviving mutants [5, 6]. Extra tests can also reject valid alternative fixes, so each new test must be validated [25]. | **Test augmentation:** feed our recorded *survivors* to an LLM to write killing tests. Keep a test only if it passes the reference and fails the survivor. This recovers rejected tasks and strengthens accepted ones. | **Yes** | Medium |
| 7 | **Some survivors may be equivalent mutants,** which makes the kill-rate threshold unfair. | LLM-based equivalent-mutant detection beats prior methods by 35.69% F1 [4]. | Classify survivors as *equivalent* (exclude) or *real gap* before applying the threshold. | Yes | Low |
| 8 | **Bugs are rule-based** (single-token). | LLM mutants mimic 77.4% of real bugs vs 41.6% for rule-based ones, but are more often non-compiling or duplicates [3]. Bugs can be synthesised by inverting real historical fixes [18]. | Optional **LLM bug generator** behind the same validation gates, which already reject non-compiling or undetected changes. | Yes | Medium |
| 9 | **Famous repos, so models may have memorised the code.** | Memorisation advantage can be measured by perturbation [26]. Semantics-preserving transforms reveal memorised repairs, with performance drops of 4–16% [27]. Refactoring cuts n-gram overlap by 75% [29]. Time-based contamination signals are fragile [28]. Syntax-aware detectors improve contamination detection [30]. | After agent runs, report a **memorisation probe**: success on original vs identifier-renamed variants of the same task. | Yes (agent runs) | Medium |
| 10 | **No evidence yet that tasks separate strong from weak agents.** | Item Response Theory (IRT) estimates per-item difficulty and discrimination and exposes low-quality items [7, 8, 13]. Small curated subsets reproduce full rankings [12]. "Strong model fails, weak model passes" flags broken items [14]. IRT extends to agentic coding [9]. Benchmark health can be summarised as discrimination and headroom [15]. Agents' token cost varies up to 30× across runs [16]. | Run **2–3 agents or models** with Harbor, fit a simple IRT model, report difficulty, discrimination and cost per task, and drop non-discriminating tasks. | Yes | Low once runs exist |
| 11 | Possible rubric-based "code quality" score. | Question-specific rubrics help [35], but LLM judges are unstable under small perturbations [36]. | **Do not** make grading judge-based. Keep execution-based rewards; a rubric could only ever be a secondary signal. | — | — |

## Recommended order (deadline 6 Dec)

**Without an AI key** (can start now):
1. Statement-deletion wrong fixes plus at least 3 wrong fixes per task (#1). This removes the largest rejection class and strengthens every task's evidence.
2. Composite *hard* tasks plus a static difficulty score (#2, #3). This gives a real easy/medium/hard spread, and Meaningful Variation is worth 20%.
3. Held-out F2P split plus a tamper log (#5). This adds reward-hacking evidence to Accuracy & Validation (25%).
4. Hint levels L1/L2 (#4). One task source then yields several difficulties.

**With an AI key:** agent runs with an IRT difficulty report (#10), then test augmentation from survivors (#6, #7).

## Limitations
- **Coverage:** OpenAlex only (arXiv and Semantic Scholar were rate-limited from this network), top 40 per query, and title screening only.
- **Unverified claims:** many sources are 2025–26 preprints, and their numbers are authors' self-reports taken from abstracts.
